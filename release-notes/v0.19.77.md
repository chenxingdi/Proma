# Proma v0.19.77 更新

本版本为自托管仓库构建版本，仅提供 Windows x64 安装包。

## 问题修复

- **自带 GitHub MCP 无法授权** — 修复「我的 MCP」目录里的 GitHub 卡片点击授权必然失败并报 `missing required Authorization header` 的问题。

  GitHub 官方远程 MCP 不提供动态客户端注册，必须由用户预先提供自建 OAuth App 的 Client ID 与 Client Secret。此前目录卡片没有处理「需要 Client Secret」这种情况，会直接发起授权并被拒绝；而唯一能弹出保存 Secret 对话框的「我的 MCP」列表，又按名称把这批目录条目过滤掉了，形成死路。

  现在目录卡片与「我的 MCP」共用同一条授权前置流程：缺少 Client Secret 时先弹出安全保存对话框，保存后自动继续浏览器授权，成功握手后启用。

- **重启后重复要求输入 Client Secret** — 是否已保存 Secret 改由主进程查询系统 Keychain 判断，不再依赖渲染进程内存标记。

- **更换 MCP 地址后误用旧密钥** — OAuth Client Secret 必须与当前配置的服务地址一致才会被使用，避免换过 endpoint 后拿旧密钥去交换授权码。

## 升级提示

若此前为绕过该问题添加过名称不同的 GitHub MCP 副本（例如 `github-oauth`），升级后可删除该副本，直接使用自带的 GitHub 卡片。
